# チェックポイントと復旧

開始位置を指定せずに起動したストリームは、サーバーの現在位置から読み始めます。プロセスが止まっている間にコミットされた変更はすべて飛ばされます。前回の続きから読むには、ストリームが公開するチェックポイントを保存し、次回の起動でそれを渡します。

## 再開する

```typescript
await using stream = new CdcStream({
  host: "mysql.example.com",
  user: "replicator",
  password: "secret",
  serverId: 1001,
  startGtid: loadCheckpoint(), // 省略するとサーバーの現在位置から始まる
});

for await (const event of stream) {
  await handle(event);
  saveCheckpoint(stream.currentGtid);
}
```

```python
async with CdcStream(
    host="mysql.example.com",
    user="replicator",
    password="secret",
    server_id=1001,
    start_gtid=load_checkpoint(),  # 省略するとサーバーの現在位置から始まる
) as stream:
    async for event in stream:
        await handle(event)
        save_checkpoint(stream.current_gtid)
```

`currentGtid` / `current_gtid` は、リーダーが最後にコミットしたチェックポイントです。ストリームを閉じたスコープを抜けても値は残るので、ループの後で 1 回だけ保存することもできます（`break` で抜けた場合も同じです）。`BinlogClient` も同じ名前で同じ組を持ちます。

## at-least-once と、その代償

配送は at-least-once です。再接続の後にイベントが再配送されることがあるので、次のようにします。

- そのイベントの処理が成功してからチェックポイントを保存します。
- その処理を冪等にします。

チェックポイントを先に保存すると、クラッシュがイベントの欠落になります。ハンドラを冪等にしておけば、再配送は何もしないのと同じになります。上の順序なら何も失いません。

## 正確な位置から始める

開始モードは 3 つあり、設定はそのうち 1 つを選びます。

| モード | 指定方法 |
| --- | --- |
| サーバーの現在位置 | `startGtid` と binlog ファイル・オフセットの組を省略する。 |
| GTID セット | `startGtid` / `start_gtid`。空文字列は空のセットから始まり、サーバーに残っているすべてが対象になる。 |
| binlog ファイルとオフセット | `startBinlogFile` と `startBinlogPosition`（4 以上。最初のイベントはファイル先頭 4 バイトのマジックナンバーの後から始まる）。 |

明示的な 2 つのモードは併用できません。指す開始位置が別々で、片方しか反映できないためです。ファイルを伴わないオフセットは、受け付けて黙って捨てるのではなく、設定の時点で拒否されます。

## GTID エントリの読み方

トランザクション番号だけを書いた MySQL のエントリは、送信前に区間へ広げられます。`uuid:N` は `uuid:1-N` から再開し、タグ付きの `uuid:tag:N` は `uuid:tag:1-N` から再開するので、1 から N-1 までのトランザクションは配送されません。`uuid:5-9` のようにすでに区間を書いたエントリは書いたまま送られ、`uuid:0` は何も足しません。

MariaDB の GTID は `domain-server-seq` の形式で、そのまま送られます。

## パージ済みの位置

サーバーがすでにパージした GTID は、黙って先頭から読み直すのではなく、コード 405 で失敗します。先頭から読み直すと、後のどの実行からも気付けない欠落が残ります。失敗する方が役に立ちます。スナップショットを取り直し、それと一緒に取得したチェックポイントから新しいストリームを始めてください。

## 自動再接続

`CdcStream` は転送の失敗後に自分で再接続し、最後に配送したチェックポイントから再開します。*N* 回目の試行は `min(N seconds, 10s)` を基準に 50〜100% のジッタを掛けた時間を待つので、待ち時間は 0.5〜1 秒、1〜2 秒と伸び、上限に達した後は 5〜10 秒になります。どちらのバインディングも同じスケジュールです。

```typescript
const stream = new CdcStream({
  host: "mysql.example.com",
  user: "replicator",
  maxReconnectAttempts: 10, // 既定は 10。0 で再接続を無効化する
});
```

試行を使い切ると、反復は元のエラーで終わります。再接続では直らない失敗——資格情報の誤り（401）、サーバー設定の拒否（402）、パージ済みの GTID（405）——は最初から再試行されません。区分の全体は[エラー](errors.md)にあります。

`BinlogClient` は再接続しません。失敗を報告し、判断は呼び出し側に任せます。

## 最初のチェックポイントを取る

スナップショットの機能はありません。このライブラリが読むのはログで、テーブルではありません。初期ロードは次の手順になります。

1. サーバーの現在の GTID セットを読み、保存します。
2. 既存の行を好きな方法で読み込みます。`mysqldump`、`SELECT`、レプリカのいずれでも構いません。
3. 手順 1 の GTID セットを `startGtid` に渡してストリームを開始します。

手順 2 の間にコミットされた変更はその位置より後のログに入るので、ストリームが配送します。重なりが害にならないのは、ハンドラが冪等だからです。
