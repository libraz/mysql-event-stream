# 用語集

### ABI version

バイナリがビルド時に対象とした C ABI の世代で、`mes_abi_version()` が返します。フィールドの追加は、古いヘッダでビルドされたバイナリがそのままリンクして動くように配置されています。新しいコードが、古いライブラリの書かないフィールドを読もうとする逆向きを拒むのが ABI バージョンです。

### ANNOTATE_ROWS

後続の行変更を生んだ SQL 文を運ぶ MariaDB の binlog イベントです。`sourceSql` / `source_sql` に届きます。1 つの注釈が対応するのは文全体であって、1 つの行イベントではありません。[MariaDB](mariadb.md)を参照してください。

### at-least-once

このライブラリの配信保証です。イベントは複数回配信されることがあります。再接続のあと、ストリームは最後にコミットしたチェックポイントから再開し、その先を再生します。exactly-once は提供していません。[チェックポイントと復旧](checkpoints.md)を参照してください。

### 変更前イメージ / 変更後イメージ（before image / after image）

行の変更前の姿と変更後の姿です。`INSERT` には変更後イメージだけ、`DELETE` には変更前イメージだけ、`UPDATE` には両方があります。完全なイメージを得るには、ソース側で `binlog_row_image=FULL` が必要です。

### binlog / binary log

サーバーが自分のデータへの変更をすべて記録したログで、レプリケーションと復旧のために書かれます。このライブラリはそれをレプリカと同じように読みます。

### binlog 位置（binlog position）

binlog のファイル名とバイトオフセットです。イベントに付くオフセットは*次の*イベントのオフセットで、再開はそこから始まります。

### CDC (Change Data Capture)

差分をポーリングして調べるのではなく、データベースの変更をイベントのストリームとして観測することです。

### チェックポイント

ストリームが再開できる位置で、`currentGtid` / `current_gtid` として公開されます。イベントの処理が成功したあとにだけ永続化してください。

### チェックサムのフレーミング（checksum framing）

イベントの末尾 4 バイトが CRC32 のトレーラかどうかです。`FORMAT_DESCRIPTION_EVENT` がストリームの途中でこれを変えることがあるため、フレーミングはクライアントから一度だけ読み取るのではなく、poll 結果に載ってイベントと一緒に運ばれます。

### COM_BINLOG_DUMP_GTID

GTID セットからストリーミングを始めるようサーバーに求めるプロトコルコマンドです。MariaDB では代わりに、GTID 位置を添えた `COM_BINLOG_DUMP` を使います。

### FORMAT_DESCRIPTION_EVENT

binlog ストリームの先頭に現れ、以降のイベントがどうフレーミングされるか、つまりヘッダ長とチェックサムアルゴリズムを示すイベントです。

### GTID (Global Transaction Identifier)

トランザクションに付く、サーバーに依存しない名前です。MySQL は `uuid:seq`、MariaDB は `domain-server-seq` と綴ります。ストリームが再開の起点にするのは GTID セットです。

### heartbeat

イベントを運ばない poll 結果です。その区間でダンプが何も生まなかったことを、サーバーがそう伝えています。健全な状態であり、エラーとは別物です。遅延メトリクスを進めるのに使えます。

### メタデータ接続（metadata connection）

`binlog_row_metadata=FULL` が効いていないときに、`SHOW COLUMNS` でカラム名を解決する 2 本目の接続です。読むのは現在のスキーマなので、リプレイには使えません。[カラム名](column-names.md)を参照してください。

### NULL bitmap

`ROWS_EVENT` の各行の先頭にあり、どのカラムが `NULL` かを示すビット列です。続くのは `NULL` でない値だけで、隙間なく詰まっています。そのため、どの値を読むにもまずビットマップを読む必要があります。

### 消去された GTID（purged GTID）

binlog がローテートで失われたために、サーバーがもう持っていないトランザクションです。これを要求すると、黙って先頭から読み直すのではなくコード 405 で失敗します。

### レプリカ識別子 / サーバー ID（replica identity / server id）

接続がソースに登録する番号で、`serverId` / `server_id` です。プロセスごとに一意にしてください。そうしないと 2 つのプロセスが互いを追い出し合い続けます。[サーバー設定](server-setup.md#レプリカ識別子)を参照してください。

### ROWS_EVENT

実際の行データを運ぶイベントで、`WRITE_ROWS`、`UPDATE_ROWS`、`DELETE_ROWS` があります。テーブルは数値 ID でしか指さず、型も持たないため、先行する `TABLE_MAP` なしにはデコードできません。

### サーバーの種別（server flavour）

ソースが MySQL か MariaDB かで、接続時に検出され `flavor` が返します。これが GTID の形式、ダンプコマンド、チェックサム変数の名前を決めます。

### TABLE_MAP_EVENT

数値のテーブル ID をデータベース名とテーブル名に結び付け、各カラムの型を記述するイベントです。符号の有無、文字セット、カラム名といった任意のメタデータは、`binlog_row_metadata` が求めたときにだけ記録されます。[変更イベント](change-events.md)を参照してください。

### トレーラの事前検証（trailer pre-verification）

各イベントの CRC32 を上流がすでに検証したという宣言で、エンジンは計算を省きます。この宣言を裏付ける仕組みはありません。検証されていないストリームに設定すると、壊れたイベントが黙って受理されます。
