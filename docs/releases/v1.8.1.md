# mysql-event-stream v1.8.1 Release Notes

**Release Date:** 2026-11-04
**Type:** Patch (no ABI change — C ABI stays at version 3)
**Previous Version:** v1.8.0

---

## Overview

The binlog wire format is now decoded by
[libmybinlog](https://github.com/libraz/libmybinlog), a separate library that
mygram-db uses as well. Event framing, checksums, `TABLE_MAP`, `QUERY`, row
images, MySQL and MariaDB GTIDs, event classification and the server-setting
rules all moved there. The decoders that used to live in `core/src` are gone,
and a wire-format fix now lands in one place for both projects.

The C ABI is untouched: no symbol, struct field or enum value moved, and
`mes_abi_version()` still reports 3. Every column value renders to the same
string it did in 1.8.0.

Moving to the shared codec fixed two real defects. Tagged GTIDs from a MySQL
8.4+ server were never tracked, and a raw `binlog_checksum=NONE` file needed a
manual framing call. It also tightened a few places where the old decoders
skipped an event or rendered a guess. Those now stop the stream with an error,
listed under Changed.

**Highlights:**

- **Tagged GTIDs reach the checkpoint** in `uuid:tag:N` form and resume as
  written
- **Checksum framing comes from each format description event**, so raw
  `binlog_checksum=NONE` files decode without configuration
- **`XA_PREPARE`, `ANONYMOUS_GTID` and `EXECUTE_LOAD_QUERY` stop the stream**
  instead of being skipped
- **Impossible column values fail** with `MES_ERR_DECODE_ROW`

## Bug Fixes

### Tagged GTIDs

MySQL 8.4 writes a tagged GTID (`uuid:tag:N`) as event type 42, whose body is a
serialized field list that begins with a format version. The old reader started
one field late, so it rejected every tagged GTID a real server sent, and the
transaction never moved `currentGtid` / `current_gtid`. A checkpoint taken on a
source using tagged GTIDs therefore lagged behind the delivered rows. They are
now parsed with the server's layout, tracked in client mode, and a checkpoint
that contains them resumes as written.

### Checksum framing

The engine reads the checksum algorithm from every `FORMAT_DESCRIPTION_EVENT`
and applies it to the events that follow. A raw binlog file opens with one, so a
file written under `binlog_checksum=NONE` decodes with no call to
`mes_set_checksum_enabled()` / `set_checksum_enabled()`. A call still frames the
events fed after it, until the next FDE replaces it. An FDE that cannot be
parsed fails with `MES_ERR_PARSE`. The previous framing used to stay in force.

### Values that cannot exist

These fail with `MES_ERR_DECODE_ROW` (202) instead of being rendered:

- a temporal field outside its range, such as month 13 or hour 24 in a
  `DATETIME`
- DECIMAL metadata outside precision 1–65 or scale 0–38
- a length prefix declared zero bytes wide
- a column type the decoder does not know

Zero dates such as `0000-00-00` are in range and still render as written.

### Other input checks

- A `QUERY` event whose status-variable block runs past its declared length is
  refused.
- Connect-time validation rejects `binlog_row_value_options` when the value
  contains `PARTIAL_JSON`. It used to reject only an exact match.

## Changed

### Events that stop the stream

`XA_PREPARE`, `ANONYMOUS_GTID` and `EXECUTE_LOAD_QUERY` now fail with
`MES_ERR_PARSE`, joining `INCIDENT`, compressed payloads and
`PARTIAL_UPDATE_ROWS`. Skipping them let the checkpoint move past changes no
consumer could be given correctly. A prepared XA transaction can still roll
back, an anonymous transaction has no GTID to checkpoint, and a statement-based
`LOAD DATA` never writes its rows to the log.

An event type the decoder does not know is skipped when the source flags it
`LOG_EVENT_IGNORABLE_F`, as a replica would. Without the flag it still stops the
stream. [Server setup](../en/server-setup.md#events-that-stop-the-stream) has
the full list.

### Building from source

CMake fetches libmybinlog from GitHub on the first configure, pinned in
`cmake/libmybinlog.cmake`, so that step needs network access. Set
`MYBINLOG_SOURCE_DIR` to build against a local checkout. The published npm addon
and Python wheels contain the codec and need nothing at install time.

### Row decoding

Rows are decoded into one scratch row kept across events and rendered as they
are visited. Integer, text and bytes values render inline, and decoded changes
are placed into the queue without a copy.

## Migration Guide

No rebuild is required for C and C++ callers, and neither binding changed its
API.

- **XA transactions:** a MySQL source that runs XA transactions now stops the
  stream at the first `XA_PREPARE`. Stream from a source that does not use XA.
- **`gtid_mode`:** a transaction logged while `gtid_mode` was not `ON` now stops
  the stream. Start after the point where GTIDs were enabled.
- **Raw `binlog_checksum=NONE` files:** the `set_checksum_enabled(False)` call
  before feeding is no longer needed. Leaving it in is harmless.
- **Building from source:** allow network access for the first CMake configure,
  or set `MYBINLOG_SOURCE_DIR`.
