# mysql-event-stream v1.8.0 Release Notes

**Release Date:** 2026-10-21
**Type:** Minor (no ABI change — C ABI stays at version 3)
**Previous Version:** v1.7.1

---

## Overview

Version 1.8.0 is mostly a correctness release. Checkpoints after a file/offset
start, malformed protocol input, runtime filter changes, Worker teardown in
Node and cancellation in Python each had a path where the library did something
other than what the documentation says. Those paths are fixed.

It is a minor version for one reason: Python's `start_binlog_position` changes
from `int = 0` to `int | None = None`, and an explicit `0` is now refused. That
is a change to a published signature. Everything else either fixes behavior or
is invisible to callers.

The C ABI is untouched. No symbol, struct field or enum value moved, and
`mes_abi_version()` still reports 3.

The npm addon now carries OpenSSL, zlib and the C++ runtime inside the binary,
so installing the package no longer depends on which OpenSSL the host has.

**Highlights:**

- **Checkpoints after a file/offset start** wait for the server's GTID state
  instead of reporting a position the stream has not reached
- **Malformed input fails closed** in frame trailers, length-encoded integers
  and GTID sets
- **Node Workers can be terminated mid-call** without aborting the process or
  waiting for the read timeout
- **Python cancellation is safe** at any point in start, reconnect and close
- **Self-contained npm addon** for linux-x64

## Bug Fixes

### Checkpoints

A stream started from a binlog file and offset has no GTID position until the
server sends PREVIOUS_GTIDS (MySQL) or GTID_LIST (MariaDB). The client now
publishes no checkpoint before that event, and an empty current GTID is
documented as "no checkpoint yet". A MariaDB group that is not standalone, such
as `CREATE TABLE ... SELECT`, checkpoints at its XID rather than at its first
event. Neither binding ever persists an empty checkpoint.

### Malformed input

- A checksummed frame shorter than its 4-byte trailer is refused.
- There is one length-encoded integer decoder. It fails on the 0xFF and 0xFB
  prefixes and on truncated bytes, where the copies it replaced read past the
  buffer or returned a value.
- `GtidSet::Parse` uses one strict grammar. It accepts tagged MySQL GTID runs
  and refuses empty colon pieces.
- MariaDB's `SET STATEMENT ... FOR <DDL>` is recognised as DDL by the engine and
  by the GTID tracker through one shared statement scanner.

### Queue accounting and limits

The queue byte budget charges each event for its per-row column arrays and for
the table metadata it pins, with a floor of 1 MiB per event, so the budget
bounds what the queue actually holds. Client limit setters return
`MES_ERR_INVALID_ARG` while the client is streaming.

### Filters

A table that a filter setter newly allows is resolved at once. Its rows carry
column names, and the missing-signedness warning fires, without waiting for
another TABLE_MAP. Strings containing U+0000 are refused with `INVALID_ARG` on
both bindings, in options and in filter entries; before this release the C ABI
saw only the part before the NUL, so a filter entry could match a different
table.

### Node.js

- An async call completing while its Worker is being torn down skips
  JavaScript, so ending a Worker with a call on the thread pool no longer aborts
  the process.
- A Worker terminated while a poll waits on the server stops the client
  immediately. It used to wait for the next heartbeat, or for the read timeout
  on a silent server.
- `BinlogClient` refuses stream-only options, `feed(null)` is refused with a
  code, the queue budget and event size combination is checked as in Python,
  and an exception thrown by `onMetadataError` propagates.

### Python

- `CdcStream` runs start, reconnect and close as tracked tasks. Cancelling the
  consumer abandons only its wait: the next `__anext__` joins the same task, so
  a handshake is never repeated and a finished poll is never dropped.
- When the retry budget runs out, the stream closes before the error is raised.
  If the awaiting call had been cancelled, the next `__anext__` now raises that
  error once instead of ending the iteration cleanly.
- Every refusal carries `INVALID_ARG`, unknown options are refused with a code,
  and `enable_metadata` raises `MesConnectionError` for a connection failure.

### TLS, authentication and logging

Handshake state is reset when a connection object is reused, the RSA scramble is
wiped on every exit path, and the OpenSSL error queue is cleared before each TLS
read and write. Structured log values are escaped.

## Changed

### Python `start_binlog_position`

`BinlogClient`, `CdcStream` and `ClientConfig` declare the offset as
`int | None = None`. `None` means no file/offset start was requested, which is
what omitting the key means on Node. An explicit `0` is now a supplied value and
is refused, as it already was on Node. The binding contract lost its per-surface
exception: the offset range is 4 through `UINT32_MAX` on both bindings.

### npm package

The linux-x64 addon links OpenSSL 3.5, zlib and the GNU C++ runtime statically
and depends only on glibc 2.39 or newer. The release build checks the addon's
dynamic dependencies and refuses to publish if any of those libraries is linked
dynamically. On another platform, the load error names the published target and
points to the build-from-source guide.

The package now includes `LICENSE` and the OpenSSL and zlib license texts, and
so do the wheels. The TypeScript declarations reference the disposable lib, so
a consumer type-checks without `@types/node`.

## Documentation

- The feed loop examples no longer re-feed a buffered partial event.
- `mes_client_destroy`, the event size defaults, column value conditions
  (signedness metadata, MariaDB JSON as text, `binlog_row_metadata` on MariaDB)
  and the event position are documented as implemented.
- What each published artifact links is stated once, in the architecture page.
- The examples act on and checkpoint only events whose column names were
  resolved, drop the old key when an UPDATE changes it, and rely on the
  package's library resolver.

---

## Testing

- Core tests for filters: a rejected table never reaches the column-name
  source, filters survive reset, an empty list lifts each filter, and a widened
  filter resolves the newly allowed table.
- Node and Python E2E tests of the delivered table set across a forced
  reconnect.
- An E2E test that terminates a Node Worker while its poll waits on a heartbeat.
- Unit tests on both bindings for embedded NUL refusal and for the
  file/offset combinations, decided by one shared predicate.
- The core E2E server probe retries for up to 30 seconds, so a container that
  reports healthy before it accepts a verified TLS login no longer skips the
  suite.

## Migration Guide

No rebuild is required for C and C++ callers.

**Python:**

- If you pass `start_binlog_position=0` to mean "no offset", pass nothing or
  `None` instead. Code such as `int(os.environ.get("POS", 0))` now raises; use
  `None` when the variable is unset.
- If you type-annotate `ClientConfig.start_binlog_position` as `int`, widen it
  to `int | None`.

**Node.js:**

- The published addon targets linux-x64 with glibc 2.39 or newer. Debian 12
  based images such as `node:22` and RHEL 8 do not meet that floor; build the
  addon from source there.
- Remove stream-only keys from options passed to `BinlogClient`.

**Both bindings:** a string option or filter entry containing U+0000 now
raises `INVALID_ARG`.
