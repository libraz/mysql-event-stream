# mysql-event-stream v1.7.0 Release Notes

**Release Date:** 2026-09-13
**Type:** Minor (additive ABI change — C ABI moves to version 3)
**Previous Version:** v1.6.1

---

## Overview

Version 1.7.0 makes two things reachable that 1.6 decided for you, and removes
the lock that kept independent engines from scaling.

The queue's byte budget is now settable. `max_queue_size` was never able to
express a memory limit, because what a single entry costs depends on the table
it came from and on any statement annotating it — measured across the benchmark
schemas, one queued event ranges from 241 bytes to 10,667.

Checksum framing now travels with the event that was read under it. A
`FORMAT_DESCRIPTION_EVENT` moves the client's framing while events read under
the previous value are still sitting in the queue, so a consumer that sampled
`mes_client_checksum_enabled()` once and applied it to every result was framing
events under a value that was never theirs. Both binding streams stopped doing
that, and the poll result carries the answer instead.

Row column arrays no longer come from a pooled memory resource. The pool
serialized every allocation and deallocation on the decode path, so the
documented way to parallelize — one `CdcEngine` per thread — worked against
itself.

## New Features

### The queue's byte budget is settable

```c
MES_API mes_error_t mes_set_max_queue_bytes(mes_engine_t* engine, size_t max_queue_bytes);
MES_API size_t mes_get_max_queue_bytes(mes_engine_t* engine);
```

`MES_DEFAULT_QUEUE_BYTES` is 48 MB and it is the bound that binds first on
anything wide: the entry count is what binds only while an event costs under
roughly 5 KB. Exposed on both bindings as `maxQueueBytes` / `max_queue_bytes`.

### Pre-verified trailers

```c
MES_API mes_error_t mes_set_trailer_pre_verified(mes_engine_t* engine, int pre_verified);
MES_API int mes_get_trailer_pre_verified(mes_engine_t* engine);
```

When a `BinlogClient` feeds an engine, each event's CRC32 has already been
verified on the client's reader thread and the engine verifies it a second time.
This declares the first verification so the second is skipped.

**Nothing verifies the promise.** Set it on a stream nothing validated and a
corrupt event is accepted in silence: no `MES_ERR_CHECKSUM`, no log record, just
a decoded row carrying whatever the corruption produced.

### The poll result carries its own checksum framing

```c
typedef struct {
  mes_error_t error;
  const uint8_t* data;
  size_t size;
  int is_heartbeat;
  int checksum_enabled;   /* new */
} mes_poll_result_t;
```

`checksum_enabled` is the framing the reader applied to that event, recorded
from the same value the reader's own CRC32 decision was made from. It is
meaningful only while `data` is non-NULL.

`mes_client_checksum_enabled()` is kept and is now documented as what it is: a
live view of the framing the reader is applying to the events it is reading
*now*, for monitoring rather than for framing a consumer.

### Declared error types

Python exports `MesError`, `MesConnectionError`, `ParseError`, `DecodeError` and
`ChecksumError`; each carries the native `code`. `MesConnectionError` derives
from `ConnectionError` rather than from `MesError`, so an existing ordered
`except RuntimeError:` / `except ConnectionError:` chain keeps running the clause
it ran before.

Node exports the `MesError` shape and an `isMesError()` guard. It is an
interface rather than a class because addon errors are constructed in C++ as
plain `Napi::Error` with properties set, which no class could satisfy through
`instanceof`. The guard requires a **numeric** `code`, which discriminates
against Node's own system errors — those carry a string `code` such as
`"ENOENT"`.

## Bug Fixes

### Checksum framing was decided by position

The synthetic dump-start ROTATE arrives with a CRC32 trailer even when the
persisted binlog mode is NONE. Framing is now established by a trailer that
verifies, not by where the event sits in the stream, and the decision is carried
per event rather than sampled once.

### Queue memory was bounded by entry count alone

The engine queue, the client's own queue and the table-map registry are each
bounded by the bytes they actually retain. The registry's eviction can now
remove several entries at once, and a replacement path that previously had no
eviction at all has one.

### Decode correctness

- DECIMAL groups are validated, and decoded unsigned
- A BIT column declared wider than 64 bits is rejected
- The packed-integer NULL marker is rejected where a length is expected
- Text versus bytes for character columns is decided in one place, and both
  families fall back to `MES_COL_BYTES` when `binlog_row_metadata=NO_LOG`
- The buffer reserve taken from an event header is capped
- A query response packet is classified by its marker, not its position

### Connection and stream lifetime

- A transport whose dump was abandoned mid-stream is retired
- Resumable dump errors and dead sockets are no longer hidden
- A restarted stream resumes from the published checkpoint
- The TLS SIGPIPE guard is held for a whole read, and large payloads are read
  directly
- Table metadata is installed as a replacement rather than written in place, and
  every `TABLE_MAP` arrival is acted on rather than only a changed one

### Credentials

The metadata connection password is wiped at the C ABI boundary, and the staged
replication password in the Node addon. Both route through one helper.

### Option validation

Both binding surfaces refuse the same configuration. Two competing start modes
are refused at construction, a start GTID naming no transaction is rejected, and
Node refuses a non-integer for an option it declares as an integer instead of
truncating it. Every refusal is presented the same way from every entry point.

### Python

Native dispatch in `CdcStream` is serialized, the log callback is detached at
interpreter shutdown, client lifecycle calls no longer block, and the library
that loads is the one belonging to the running environment rather than whatever
the system search finds.

## Changed

### Row column storage

Every row's column array is allocated from `std::pmr::new_delete_resource()`.
That it is *one stateless* resource for the whole process is a correctness
constraint, not a convenience: `std::pmr::polymorphic_allocator` has
`propagate_on_container_move_assignment == false`, so a move between containers
with unequal resources silently degrades into an element-wise copy. A row is
moved from the decoder into the queue and out again through `NextEvent()`, so a
per-engine or thread-local resource would turn each hop into a deep copy.

Queued memory per event fell with the pool, which had been rounding each column
array up to its block size:

| Workload | 1.6.1 | 1.7.0 |
|---|---:|---:|
| `wide28_update_x1` | 6,114 B | 4,659 B |
| `wide28_write_x50` | 2,677 B | 2,421 B |
| `temporal7_write_x1` | 723 B | 657 B |

### Per-row work removed

An event's column names and annotating statement are shared rather than copied
per row, and a DECIMAL is rendered from the digits it produces rather than from
its declared width.

## Testing

Unit suites: 1,000 core, 352 Node, 564 Python.

End-to-end, against live servers: 112 core cases against MySQL 8.4, 20 Python
cases against the same, and 23 Node cases against MariaDB 11.4. The MariaDB and
VECTOR cases skip on a server that does not provide them.

Thread scaling, one independent `CdcEngine` per thread, median of three rounds,
aggregate row events/sec:

| Workload | 1t | 2t | 4t | 8t |
|---|---:|---:|---:|---:|
| `temporal7_write_x1` | 3,655,937 | 1.89x | 3.51x | 5.31x |
| `strings7_write_x1` | 4,072,881 | 1.81x | 3.44x | 5.50x |
| `wide28_write_x50` | 1,998,903 | 1.51x | 2.27x | 4.78x |

Measured on 6 performance and 12 efficiency cores, which is why eight threads
returns 4.8-5.5x rather than 8x. The recorded 1.6 baseline fell past each
workload's peak instead of rising.

## Migration Guide

**A binary built against the 1.6 header keeps working.** `mes_poll_result_t` is
still 32 bytes and its four original fields are still at offsets 0, 8, 16 and
24; the new field occupies what was tail padding. No symbol was removed or
changed.

**Rebuild before using the new field.** Code built against the 1.7 header reads
`checksum_enabled` at offset 28, which a 1.6 library never writes. That
direction is what `mes_abi_version()` moving to 3 refuses: the Python binding
checks it at load and will not run against a 1.6 library.

**Review these changes:**

- If you framed a raw engine from `mes_client_checksum_enabled()` sampled once
  after start, take the value from the `checksum_enabled` field of each result
  you feed instead. Both binding streams already do this internally; only code
  driving a `CdcEngine` from a `BinlogClient` by hand is affected.
- If you construct a `PollResult` yourself — a test double, most likely — it now
  carries a third member on both bindings.
- If you passed a fractional number to a Node option declared as an integer, it
  was truncated and is now refused. `maxQueueSize`, `maxQueueBytes` and
  `maxEventSize` are refused through their engine setters as well.
- If you caught a bare `RuntimeError` from a Python call that failed with a
  native code, the raised type is now `MesError`, which derives from it. An
  `except RuntimeError:` clause still matches.
- If you need a memory limit on the queue, use `mes_set_max_queue_bytes()`.
  `max_queue_size` cannot express one.
