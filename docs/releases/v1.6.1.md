# mysql-event-stream v1.6.1 Release Notes

**Release Date:** 2026-08-15
**Type:** Patch (no ABI change — C ABI stays at version 2)
**Previous Version:** v1.6.0

---

## Overview

Version 1.6.1 closes the gap between what 1.6.0 documented and what it
delivered. MariaDB statement text never actually arrived, an empty reconnect
checkpoint could ask a server for its entire retained binlog, and a table
mixing ENUM, SET, or VECTOR columns with character columns could assign a later
column the wrong collation. Each of those is fixed here, along with a set of
hardening changes in the protocol and decode paths.

The C ABI is untouched: no symbol, struct field, or enum value was added,
removed, or moved, and `mes_abi_version()` still reports 2. A caller built
against the 1.6.0 header links against this library without recompiling. What
did change is behavior — several silent failures are now loud, both bindings
validate their options identically, and a batch poll no longer discards the
events that preceded a terminal error.

**Highlights:**

- **MariaDB `source_sql` works** — the dump request now asks for ANNOTATE_ROWS,
  which the slave capability alone does not imply
- **Checkpoints stop running ahead of delivery** — MariaDB standalone GTID
  groups checkpoint at their terminating event, and an empty reconnect
  checkpoint is never forwarded as a resume position
- **Charset index space corrected** — ENUM and SET no longer consume a
  `DEFAULT_CHARSET` slot; VECTOR does
- **`mes_client_stop()` interrupts `mes_client_start()`** instead of waiting for
  the whole startup handshake
- **Events before a terminal error are delivered** rather than dropped with the
  batch
- **A shared contract** fixes error retryability, backoff, and option ranges for
  both bindings in one file, verified by a test on each side

## Bug Fixes

### MariaDB statement text never arrived

`mes_event_t::source_sql` shipped in 1.6.0, but MariaDB only sends
`ANNOTATE_ROWS` events when the dump request sets the corresponding flag —
negotiating `@mariadb_slave_capability` is not enough on its own. The flag is
now set on every MariaDB dump, so annotated row events carry the original
statement. The statement is decoded once per event and shared by all of its
rows instead of being copied into each one.

### Checkpoints could advance past undelivered rows

A MariaDB standalone GTID group — one with no COMMIT or XID, such as DDL or a
single autocommit statement — was checkpointed at its GTID event, which arrives
before the group's own payload. A consumer that resumed from that checkpoint
skipped the change. Checkpointing now waits for the group's terminating event:
the STMT_END row event, or the terminating query for standalone DDL.

Separately, a GTID that cannot merge into the tracked set (for example when a
SID's interval capacity is exhausted) used to be dropped silently. It is now
logged as `gtid_checkpoint_merge_failed` and kept pending, so the checkpoint
stalls visibly rather than advancing past a gap.

### An empty reconnect checkpoint asked for the whole binlog

When a connection dropped before any commit was seen — or when the stream was
anchored to a file and offset, which yields no GTID — both bindings forwarded
an empty string as the resume GTID set. A server reads that as a request for
every binlog it still retains. The configured start mode is now kept verbatim
until a real checkpoint has been published, and the last checkpoint stays
readable after the stream is closed.

### ENUM, SET, and VECTOR shifted the charset index space

TABLE_MAP's `DEFAULT_CHARSET` and `COLUMN_CHARSET` metadata is indexed over
character columns only. ENUM and SET travel on the wire as `MYSQL_TYPE_STRING`
but are excluded from that index space, because the server carries their
collations in the separate `ENUM_AND_SET_*` fields; VECTOR does occupy a slot,
always with the binary collation. Counting ENUM and SET as character columns
shifted every later column's collation by one, which could surface a `VARCHAR`
as bytes or a binary column as text. The counting now follows the real wire
type behind `MYSQL_TYPE_STRING`.

### Stop could not interrupt a start

`mes_client_start()` performs several blocking round trips and used to hold the
lifecycle lock across all of them, so `mes_client_stop()` from another thread
blocked until startup finished or timed out. Startup is now split into stages
with the stop state re-checked between them; an interrupted start returns
`MES_ERR_DISCONNECTED`, and a stop shuts the transport down for good, so every
later start returns `MES_ERR_DISCONNECTED` until `mes_client_connect()`
establishes a new one. Two concurrent starts are refused with `MES_ERR_STREAM`
rather than serialized.

### Filter setters

A filter entry without a `.` is compared against the bare table name only, so a
prefix wildcard such as `log*` no longer matches on the database name of an
unrelated table. A NULL element inside a filter array used to be skipped
silently, which partially or fully cleared the installed filter; the whole call
is now rejected with `MES_ERR_NULL_ARG` and the previous filter stays in place.

### Protocol and decode hardening

**Framing.** Artificial ROTATE detection may only turn checksum presence on; it
no longer re-derives the flag mid-event, which could reframe the event being
parsed.

**Connect timeout.** The timeout applied per resolved address, so a dual-stack
hostname could block for twice the configured value. One deadline is computed
once and the remaining time is used for each candidate.

**Authentication.** The auth plugin name is validated against the supported set
before the empty-password shortcut, so an unsupported plugin is rejected rather
than answered with an empty response. The full-authentication failure message
now names both remedies: raising `ssl_mode` to `verify_ca` or `verify_identity`,
or opting into `allow_public_key_retrieval`.

**Result sets.** Column-name bytes count against the result byte budget, which
could previously be exceeded before any row value was read. Column-definition
packets and repeated empty row packets are bounded, and transport or framing
failures report `MES_ERR_STREAM`.

**Row decoding.** A per-event decode budget is charged across all rows and both
update images, independent of the per-field decompression cap, and the wire
column count is cross-checked against TABLE_MAP before any bitmap arithmetic.
Bitmap sizing saturates instead of wrapping, and variable-length prefix sizes
are overflow-guarded.

**Lifetimes and payloads.** The metadata fetcher is now guaranteed to outlive
the engine that uses it regardless of member declaration order. A payload longer
than `UINT32_MAX` is clamped and reported through the log callback as a
`column_data_truncated` warning instead of asserting.

**Credentials.** Protocol packet buffers wipe their storage on clear and
destruction and reserve capacity up front, so a reallocation cannot leave a
stray plaintext copy behind; the staging copy of the password is wiped after
connect.

### Event classification

Every event type a supported server can emit is now classified explicitly:
decoded, advanced silently as a control event (STOP, ROTATE, XID, INTVAR, RAND,
USER_VAR, the load-query family, XA_PREPARE, heartbeat, format description, the
GTID family, and the MariaDB equivalents), or refused with `MES_ERR_PARSE`
(INCIDENT, transaction payload compression, partial JSON and partial row
updates, the MariaDB compressed events). A type code no supported server emits
also fails, so a newly introduced event type is loud rather than lossy.

### Bindings

Both bindings validate every option at construction the same way `configure()`
does — construction previously skipped the range checks — and range-check batch
size and log level against the shared contract instead of ad hoc literals. Every
error crossing the native boundary carries a numeric error code, so a permanent
lifecycle violation is never misclassified as a transient failure and retried.

A tagged MySQL GTID naming a bare transaction number (`uuid:tag:5`) is widened
to `uuid:tag:1-5`, matching the untagged form; previously only the untagged form
was widened and a tagged entry went out as written.

## Changed

### Events before a terminal error are delivered

`poll_batch` / `pollBatch` used to discard the whole batch when its final
element carried a terminal error. The native checkpoint advances as if the batch
had been consumed, so those events were lost permanently. The events are now
delivered and the terminal error is latched and reported on the next call.

### Error codes for transport failures

Query-layer failures caused by the transport or by malformed framing report
`MES_ERR_STREAM` rather than `MES_ERR_PARSE`. Callers that match on the specific
code should expect the new one.

### Queue byte accounting

The client byte budget charges only the buffered wire payload. Checkpoint text
and error messages are no longer counted against it, and the admission check at
start compares the configured budget against the minimum one maximum-size event
requires, rather than against the event size alone.

### Option validation is stricter

Because both bindings now apply the full range checks at construction, an option
that was previously accepted out of range — batch size, log level, or any value
covered by the shared contract — raises immediately instead of being clamped or
passed through.

### Python column marshalling

`_convert_columns` copies payloads through a single `ctypes` window over the C
buffer instead of one `string_at` call per column, and orders its type branches
by observed frequency. Output is unchanged; a differential test compares it
against a naive reference implementation.

### Node toolchain

The binding pins Node and Yarn with mise instead of volta, moves to Yarn 4.18,
and tightens `.yarnrc.yml`. This affects contributors only, not the published
package.

## New Features

### Shared binding contract

`core/contracts/bindings.json` is the single source for the behavior both
bindings must agree on: which error codes are retryable, the reconnect backoff
schedule, the checkpoint-resume rule, the poll-batch and log-level windows, and
the shared option defaults and ranges. Each binding mirrors it as typed
constants — `contract.ts` and `_contract.py` — and a contract test on each side
compares the constants against the JSON, so a value edited in one place without
the other fails that binding's suite instead of drifting silently.

### Benchmarks

Three harnesses ship under `core/benchmarks`: synthetic decode workloads, a
loopback socket-read path, and an allocation-tracking variant of the workload
run, with their measured baseline recorded alongside. `make benchmark` runs the
feed, workload, and memory harnesses; `make benchmark-socket` runs the socket
path separately because it moves gigabytes; `make benchmark-python` measures the
Python column-marshalling path against generated events.

### Security policy

`SECURITY.md` documents the private disclosure process, the supported version
table, and what is in and out of scope for a binlog-protocol client.

## Testing

- New unit suites for client startup and stop interaction, the extracted
  handshake payload parser (including truncation at every byte offset and every
  declared auth-data length), the query-layer guard rails, and credential
  scrubbing.
- Row decoder, TABLE_MAP, and `binary_util` coverage for the decode budget,
  column-count overflow, the ENUM/SET/VECTOR charset index space, and the
  fixed-width temporal formatting that replaced `snprintf` on the hot path.
- Fuzzing feeds every corpus input with checksums both enabled and disabled — a
  checksummed run rejects mutated bytes at the CRC gate before the row decoder
  sees them — with new regression seeds for a column-count overflow and a
  no-checksum stream, plus a fuzz target for the handshake parser.
- E2E suites cover start-mode checkpoint and checksum state, VECTOR columns
  against MySQL 9, `binlog_row_metadata=FULL` name resolution, and MariaDB
  ANNOTATE_ROWS, in the core and in both bindings.
- Plaintext authentication E2E tests no longer depend on an earlier TLS
  connection having warmed the server's password cache.

## Migration Guide

No rebuild is required. The C ABI is unchanged and a 1.6.0 caller links against
this library as is.

**Review these behavior changes:**

- If you match on `MES_ERR_PARSE` for query failures, transport and framing
  failures now report `MES_ERR_STREAM`.
- If you passed an out-of-range batch size or log level to a binding
  constructor, it now raises instead of being accepted. The valid ranges are in
  `core/contracts/bindings.json`.
- If your consumer discarded a batch whose final element carried a terminal
  error, it was already losing events; deliver the earlier elements and handle
  the error afterwards.
- If a filter array in your C code contains NULL entries, the setter now fails
  with `MES_ERR_NULL_ARG` instead of silently installing a shorter filter.
- If you relied on a bare filter entry such as `log*` matching database names,
  it now matches table names only. Qualify the entry as `database.table` to
  match against a database.
- MariaDB consumers will start receiving `source_sql`, and MariaDB standalone
  GTID checkpoints now advance one event later than before. A checkpoint stored
  by 1.6.0 remains valid.

**Optional adoption:**

- Read `source_sql` on MariaDB sources; it is now populated.
- Use `make benchmark` and the recorded baseline when evaluating a change to the
  decode or socket paths.
