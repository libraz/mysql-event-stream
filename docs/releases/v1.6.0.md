# mysql-event-stream v1.6.0 Release Notes

**Release Date:** 2026-07-29
**Type:** Minor (additive API, ABI version 2 — recompile required)
**Previous Version:** v1.5.0

---

## Overview

Version 1.6.0 makes the stream harder to corrupt silently and cheaper to
consume. Events the engine cannot represent now stop the stream instead of
being skipped, column text and binary types are decided from TABLE_MAP charset
metadata rather than guessed from the column type, and a batched poll entry
point removes one call per event from both bindings.

The C ABI moves to version 2. No symbol was removed and no existing field moved,
but `mes_client_config_t` and `mes_event_t` gained trailing fields, so callers
compiled against the 1.5 header must be rebuilt. `mes_abi_version()` exists so a
binding can detect a mismatched library at load time instead of misreading a
struct.

**Highlights:**

- **Batched polling** — `mes_client_poll_batch()` blocks once and drains the
  rest of the queue, exposed as Node `pollBatch()` and Python `poll_batch()`
- **Explicit start positions** — choose between the server's current GTID set,
  an exact GTID set, and a binlog file plus offset
- **Purged-GTID diagnosis** — a checkpoint the source has already purged returns
  `MES_ERR_GTID_PURGED` instead of a dropped connection
- **Tagged GTIDs** — MySQL 8.4 `uuid:tag:1-5` sets parse, merge, and encode
- **Charset-aware decoding** — binary `VARCHAR` decodes as bytes, non-binary
  BLOB-family columns decode as text
- **No silent skips** — unknown and unsupported events, and partial row images,
  fail rather than advancing the caller's checkpoint past unseen changes

## New Features

### 1. Batched polling

`mes_client_poll_batch(client, results, capacity, &count)` blocks for one result
and then drains whatever is already queued, up to `capacity`. A terminal result
is included as the final element, and every `data` pointer stays valid only
until the next poll or batch call. Node exposes `pollBatch(maxEvents = 64)` and
Python `poll_batch(max_events=64)`; both stream implementations now use it, so a
burst of queued events costs one crossing of the language boundary instead of
one per event.

### 2. Explicit start positions

`mes_client_config_t` gained `start_position_mode` (`MES_START_AT_CURRENT`,
`MES_START_AT_GTID`, `MES_START_AT_POSITION`) plus `binlog_file` and
`binlog_position`. This separates three cases that previously had to be encoded
in one string: snapshot the server's current GTID set, resume from an exact GTID
set (including a deliberately empty one, which reads from the beginning of the
retained binlog), or resume from a file and offset. Bindings expose
`startBinlogFile` / `startBinlogPosition` and `start_binlog_file` /
`start_binlog_position`; a zero-initialized C config still means "start at
current", and a non-empty `start_gtid` still selects GTID resume.

### 3. Purged-GTID detection

Before issuing `COM_BINLOG_DUMP_GTID`, the client reads
`@@GLOBAL.gtid_purged` and checks that the purged set is a subset of the
requested set. If it is not, `mes_client_start()` returns the new
`MES_ERR_GTID_PURGED` (405) with a message naming the gap. Server error 1236
maps to the same code, so both the pre-flight check and a mid-stream failure are
reported identically instead of surfacing as a bare disconnect.

### 4. Tagged GTID support

GTID parsing, merging, and binary encoding moved into a shared `GtidSet` used by
the resume encoder and the transaction tracker. It understands the MySQL 8.4
tagged format in both text (`uuid:tag:1-5`) and binary form, and the tracker
decodes `GTID_TAGGED_LOG_EVENT`. Tagged sets were previously rejected with an
invalid-argument error.

### 5. Charset-aware column typing

TABLE_MAP optional metadata fields for default and per-column charsets are now
parsed. A column whose collation is binary decodes as `MES_COL_BYTES` even if it
is a `VARCHAR`, and a BLOB-family column with a known text charset decodes as
`MES_COL_STRING`. When a server omits the metadata (`binlog_row_metadata=NO_LOG`),
BLOB-family columns stay bytes as a conservative fallback.

### 6. Version, ABI, and error introspection

`mes_version()`, `mes_abi_version()`, and the `MES_VERSION_*` / `MES_ABI_VERSION`
macros identify the build; both bindings compare the ABI version when they load
the library and refuse a mismatch. `mes_error_string()` returns stable text for
every code, replacing the message tables each binding maintained separately.
`mes_client_flavor()` reports the detected server flavor and
`mes_client_crc_errors()` counts CRC32-invalid events.

### 7. MariaDB statement text

`mes_event_t::source_sql` carries the original statement from an
`ANNOTATE_ROWS` event, exposed as Node `sourceSql` and Python `source_sql`. It
is an empty string when the source did not send one.

### 8. Stream-level filtering in the bindings

`CdcStream` accepts `includeDatabases` / `includeTables` / `excludeTables`
(Node) and the same options in Python, applies them at start, and re-applies
them after a reconnect. Filter entries match byte-exactly and case-sensitively;
a trailing `*` is a prefix wildcard (`mydb.audit_*`). If include filters saw
TABLE_MAP events but never matched, a one-shot `include_filter_matched_nothing`
warning is logged — the common symptom of a filter typo used to be silence.

## Changed

### ABI version 2 — recompile required

`mes_client_config_t` gained `start_position_mode`, `binlog_file`, and
`binlog_position`; `mes_event_t` gained `source_sql`. Existing fields keep their
offsets and no symbol was removed, so source stays compatible, but a caller
built against the 1.5 header passes a shorter config than the library expects.
Rebuild against the new header.

### Unrepresentable events stop the stream

`PARTIAL_UPDATE_ROWS`, the MariaDB compressed event types, and any unrecognized
event type return `MES_ERR_PARSE`. Previously an unknown type was ignored, which
let a consumer checkpoint past changes it never received. Row events whose
columns-present bitmap has cleared bits are rejected for the same reason: the C
ABI cannot distinguish an absent column from a NULL one, so sources must run
`binlog_row_image=FULL`.

### Queue defaults and accounting

The client byte budget defaults to 48 MiB (was 256 MiB) and the maximum event
size to 32 MiB (was 64 MiB), so the default event size always fits the default
budget. Charged bytes are computed from payload size rather than allocator
capacity, and now include queued error messages. On the engine side,
`mes_set_max_queue_size(0)` restores the bounded default of 10000 events instead
of selecting an unbounded queue.

### `mes_reset()` keeps decoded events

Reset clears parser, table-map, position, and error state, but no longer discards
events already decoded. An error that follows valid events in the same input can
now be recovered by resetting and draining what was decoded before it.

### Security defaults

`caching_sha2_password` full authentication sends the cleartext password only
when TLS has verified the server certificate. Both bindings default their SSL
mode to preferred rather than disabled and reject `server_id` 0 at construction.

### Binding behavior

Both stream implementations classify parse, checksum, decode, queue-full, and
GTID errors as permanent and stop reconnecting, and reset the retry budget only
after an event is decoded rather than when any bytes arrive. Python
`start_gtid=None` snapshots the current position while `""` requests an explicit
empty set, and the engine raises `ParseError` for an unrepresentable event
instead of warning and returning nothing.

### MariaDB specifics

A failed `@mariadb_slave_capability` negotiation is now fatal instead of a
warning, validation rejects `log_bin_compress=ON`, and "start at current"
prefers `@@GLOBAL.gtid_binlog_pos` over `gtid_current_pos` so the client does
not request GTIDs the server never wrote to its own binlog.

## Bug Fixes

**Reader thread and sockets.** The socket descriptor is atomic and its shutdown
and close are serialized, so a concurrent stop cannot shut down a reused
descriptor. A finished reader thread is joined before it is replaced, stop
interrupts an in-flight handshake, and the queue is closed on every reader exit
path.

**TLS and I/O.** The handshake runs under the read-timeout deadline instead of
blocking indefinitely, verify modes without an explicit CA load the system trust
store, and readiness is checked before hangup flags so a final TLS record
delivered together with a close is not discarded.

**Result sets.** A row whose first field is 16 MiB or larger is no longer
mistaken for the end-of-rows marker, server error packets are classified as
validation errors, retained results are bounded, and a connection abandoned
mid-result-set is poisoned rather than reused.

**Decoding.** `FORMAT_DESCRIPTION` checksum detection verifies the CRC32 trailer
instead of trusting the algorithm byte. SIGNEDNESS metadata accounting was
corrected for TYPED_ARRAY, DECIMAL, and YEAR columns, and a truncated bitmap is
rejected. Fractional seconds are emitted at the column's declared precision, and
`SET` and `BIT` values above `INT64_MAX` are returned as exact decimal strings
instead of wrapping negative.

**Engine.** A parse error raised after an event was accepted no longer makes
`mes_feed()` reprocess the same event indefinitely. An artificial ROTATE with an
empty filename updates only the offset instead of clearing the resume filename.
The TABLE_MAP registry evicts least-recently-used entries instead of clearing
itself, and a byte-identical repeated TABLE_MAP skips re-parsing.

**Metadata resolution.** Failed lookups are cached and reconnects are throttled,
so a missing SELECT privilege no longer produces a query and reconnect storm.
The cache is bounded and reported.

**Checkpoints.** `ROLLBACK TO SAVEPOINT` and DDL keywords inside an open
transaction no longer promote a checkpoint, and MariaDB standalone GTID groups
are committed immediately.

**Bindings.** A throwing Node log handler can no longer surface as an uncaught
exception; `connect()`, `start()`, and `disconnect()` are rejected while a poll
is in flight; the column-name cache verifies the underlying bytes before reusing
an interned string. Python retains unconsumed `feed()` bytes instead of dropping
them, and serializes close, stop, and property reads against the poll lock.

## Testing

- New unit suites for the connection handshake and the shared GTID set, plus
  expanded coverage of batch polling, start-position validation, purged-GTID
  handling, charset classification, and the error-string surface.
- A protocol-parser fuzz target alongside the existing feed target, with a
  seeded corpus entry for MySQL 8.4 temporal rows, and a standalone smoke mode
  so the corpus runs without a fuzzing toolchain.
- E2E servers run with `binlog-row-metadata=MINIMAL` so the suites exercise the
  path where names and charsets come from TABLE_MAP alone, with new fixture
  tables for charset, signedness, and extended type mapping.
- The reader-thread E2E tests run under ASan, UBSan, and TSan in CI against a
  real MySQL container.
- `make benchmark` measures synthetic feed and decode throughput, latency, and
  RSS.

## Migration Guide

**Rebuild against the new header.** Source stays compatible, but
`mes_client_config_t` and `mes_event_t` grew. If you link the shared library
from your own C or C++ code, recompile; bindings check `mes_abi_version()` and
will refuse a stale library rather than misread a struct.

**Review these behavior changes:**

- If your source runs `binlog_row_image=MINIMAL` or `NOBLOB`, streaming now
  fails instead of reporting absent columns as NULL. Switch the source to
  `FULL`.
- An unknown or unsupported event type now returns `MES_ERR_PARSE`. If you
  previously relied on such events being skipped, handle the error and decide
  explicitly whether to resume past them.
- If you called `mes_set_max_queue_size(0)` to request an unbounded engine
  queue, you now get the bounded default of 10000 events. Raise the limit
  explicitly if you need more.
- The client byte budget and maximum event size defaults dropped to 48 MiB and
  32 MiB. Set them explicitly if your workload needs the old headroom.
- `mes_reset()` no longer empties the event queue. Drain with
  `mes_next_event()` after a reset if you expect a clean slate.
- Python callers that passed `start_gtid=""` to mean "start at current" should
  pass `None`; `""` now requests an explicit empty GTID set.
- Both bindings now default to preferred TLS rather than disabled. Set the mode
  explicitly — `verify_ca` or `verify_identity` for credentials that need
  MITM protection.

**Optional adoption:**

- Switch to `poll_batch` / `pollBatch` for high-rate streams.
- Use `start_position_mode` (or the binding options) instead of encoding intent
  in `start_gtid`.
- Handle `MES_ERR_GTID_PURGED` by reprovisioning from a snapshot rather than
  retrying.
- Read `source_sql` on MariaDB sources that enable `ANNOTATE_ROWS`.
