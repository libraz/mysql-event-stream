# mysql-event-stream v1.7.1 Release Notes

**Release Date:** 2026-09-29
**Type:** Patch (no ABI change — C ABI stays at version 3)
**Previous Version:** v1.7.0

---

## Overview

Version 1.7.1 makes the library do what 1.7.0 documented. The documented remedy
for a cold `caching_sha2_password` cache over unverified TLS could never
succeed, several error codes named a different failure than the one that
occurred, and both bindings could report a checkpoint ahead of the rows they had
delivered. Each of those is fixed here.

The C ABI is untouched: no symbol, struct field, or enum value was added,
removed, or moved, and `mes_abi_version()` still reports 3. A caller built
against the 1.7.0 header links against this library without recompiling. What
changed is behavior — error codes are narrower, and both bindings refuse a few
option values they previously accepted or coerced.

**Highlights:**

- **Opted-in full authentication works over preferred/required TLS** — the
  password is sent over the TLS session instead of requesting an RSA key the
  server then misreads
- **Error codes say what happened** — `MES_ERR_CONNECT` for transport failures
  during connect, `MES_ERR_AUTH` only for a rejected credential,
  `MES_ERR_GTID_PURGED` only on a confirmed purge
- **Checkpoints stay behind delivery** on both bindings' `CdcStream`
- **Node no longer blocks the event loop** while opening the metadata connection
- **Documentation tree** — `docs/en` and `docs/ja` replace the long READMEs

## Bug Fixes

### Full authentication over unverified TLS

When `caching_sha2_password` needs full authentication (the server's password
cache is cold), the client has two ways to deliver the password: in cleartext
over a TLS session, or encrypted with the server's RSA key on a plaintext
connection. With `ssl_mode` set to preferred or required and
`allow_public_key_retrieval` enabled, the client took the RSA path even though
TLS was active. The server reads anything sent over TLS at that step as the
password itself, so the request for the key was refused as a wrong password.
The documented remedy therefore always failed.

With the opt-in, the password is now sent over the TLS session. Without it, an
unverified TLS session still refuses full authentication, and the message now
names only the remedies that work: raising `ssl_mode` to `verify_ca` or
`verify_identity`, or opting into `allow_public_key_retrieval`.

### Error codes

- Transport failures during the handshake, and failures before any credential is
  sent, report `MES_ERR_CONNECT`. `MES_ERR_AUTH` means the server rejected the
  credential.
- The validation queries run at connect pass their own error code through. A
  transport lost during validation reports `MES_ERR_STREAM`; `MES_ERR_VALIDATION`
  means the server answered and the answer was unacceptable.
- Server error 1236 maps to `MES_ERR_GTID_PURGED` only when the server's message
  confirms purged GTIDs. Any other 1236 reports `MES_ERR_STREAM`.
- When the greeting names an auth plugin the client does not support, the client
  answers and lets the server's AuthSwitch pick a supported one, instead of
  failing locally.

### Stream lifecycle

Start, poll and batch poll share one terminal-error path, including a
`MES_ERR_DISCONNECTED` during the start drain window. Closing the descriptor is
serialized against `mes_client_stop()`. The TLS read and write timeout applies
to each stall rather than to the whole call, so a slow but progressing transfer
is no longer cut off.

The engine clears ANNOTATE_ROWS text at the statement end, so a later
unannotated statement does not inherit it, and releases the last returned event
when the engine is destroyed.

### Metadata lookups

- The reconnect throttle is measured from the end of the connect attempt. A
  connect slower than the throttle interval used to re-arm immediately, so every
  TABLE_MAP paid another blocking attempt.
- Column names already cached are served while the metadata connection is down.
- A negative entry — a table that could not be read, or whose column count did
  not match the binlog — expires after 30 seconds, so a later GRANT or a
  transient server error is retried without waiting for DDL.

### Checkpoints in both bindings

`CdcStream` polled the client while bytes from the previous poll were still
undrained in the engine, and the checkpoint it reported could then cover rows
not yet delivered. Neither binding polls with undrained bytes now. A feed
failure still delivers the events decoded before it.

### Node.js

- The metadata connection is opened on the libuv thread pool instead of
  synchronously on the event loop, at start and on every reconnect. Destroying
  the engine while that connect is in flight defers the free until it completes.
- Client options refuse out-of-range `serverId` and timeouts and unknown keys,
  matching Python, instead of wrapping or ignoring them.
- `CdcEngine.enableMetadata` validates against the connection options only, so
  stream-only keys such as `includeTables` are refused.
- The filter arrays are copied at construction and in `configure()`, so mutating
  the caller's array cannot change the filters applied on a reconnect.
- An unknown event type maps to `MES_ERR_PARSE`, as in Python.

### Python

- `include_databases`, `include_tables` and `exclude_tables` were coerced with
  `list(x or [])` before validation, so a bare string became a per-character
  filter and `""` or `0` meant no filter. Only `None` means unset now; every
  other value is validated as given. `configure()` accepts `None` for these
  options as a reset to empty.
- Every argument rejection carries the `INVALID_ARG` code, and `connect()`
  raises `MesConnectionError` only for connection codes.
- Closing or cancelling during a start or reconnect no longer latches the client
  or backs it off.
- A failure to load the native library carries the `INVALID_ARG` code, so a
  stream treats it as permanent instead of retrying it.

### Both bindings

`maxQueueBytes` / `max_queue_bytes` reaches the engine as well as the client.
The queue limits are bounded at `Number.MAX_SAFE_INTEGER` in the shared contract
and both mirrors, and an empty `startBinlogFile` is refused at construction.

### Examples

The Python examples close the stream from SIGINT/SIGTERM handlers, so they exit
while a poll is blocked on an idle server. The Node and Python examples opt into
public-key retrieval for the local test server, with a comment pointing
production code at verified TLS, so a cold password cache does not refuse them.
`search-index-sync.ts` now prints what its documented output shows.

## Changed

### Narrower error codes

Code that matches on `MES_ERR_AUTH`, `MES_ERR_VALIDATION` or
`MES_ERR_GTID_PURGED` will see those codes less often: transport failures move
to `MES_ERR_CONNECT` or `MES_ERR_STREAM`, and an unconfirmed 1236 reports
`MES_ERR_STREAM`.

### Stricter option validation

Node refuses unknown client option keys and out-of-range numeric options. Python
refuses filter values it previously coerced. `enableMetadata` in Node refuses
stream-only keys.

## Migration Guide

No rebuild is required. The C ABI is unchanged and a 1.7.0 caller links against
this library as is.

**Review these behavior changes:**

- If you retry or alert on `MES_ERR_AUTH`, transport failures during connect now
  report `MES_ERR_CONNECT`, which is retryable.
- If you treat `MES_ERR_VALIDATION` as a server configuration problem, a lost
  connection during validation now reports `MES_ERR_STREAM`.
- If you rely on `MES_ERR_GTID_PURGED` for every error 1236, only a confirmed
  purge reports it now; any other 1236 is `MES_ERR_STREAM`, which is retryable.
- Node: remove unknown keys from client options, and pass only connection
  options to `enableMetadata`.
- Python: pass filters as a list or tuple of strings, or `None`. A bare string,
  `""` or `0` now raises.
- If you worked around the cold-cache authentication failure by switching to a
  verified `ssl_mode`, that remains the recommended configuration; the opt-in
  now also works over preferred or required TLS.
